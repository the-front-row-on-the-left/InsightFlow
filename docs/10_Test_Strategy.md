# Test Strategy

## 1. 테스트 목표

- 요청이 Gateway를 반드시 통과하는지 확인
- 정책과 제한이 의도대로 동작하는지 확인
- 사용량과 비용 집계가 누락 없이 수행되는지 확인
- 병렬 개발 후 통합 시 계약이 깨지지 않는지 확인

## 2. 테스트 분류

| 테스트 종류 | 대상 | 주체 |
|-------------|------|------|
| Unit Test | 각 서비스 내부 로직 | 각 담당 |
| Contract Test | API/Event 계약 | 전체 |
| Integration Test | Gateway ↔ 하위 서비스, Kafka 소비 | B, C |
| E2E Test | UI → 실행 → 비용 조회 | A 주도, 전체 지원 |

## 3. 핵심 테스트 시나리오

### 시나리오 1: 정상 실행
1. 사용자가 서비스 실행 요청
2. Gateway 정책 통과
3. Rate Limit 통과
4. 외부 AI 호출 성공
5. Usage 저장
6. Billing 계산
7. 결과 조회 가능

### 시나리오 2: 정책 차단
1. 금지 모델 요청
2. Gateway에서 차단
3. 정책 차단 이벤트/로그 남음
4. UI에서 명확한 에러 표시

### 시나리오 3: 요청 제한 초과
1. 동일 사용자 연속 호출
2. Rate Limit 초과
3. 429 응답
4. Usage 분석 가능

### 시나리오 4: 비용 추천 생성
1. 고비용 사용 패턴 누적
2. Recommendation 생성
3. UI 또는 조회 API에서 추천 노출

## 4. 인수 기준

| 항목 | 기준 |
|------|------|
| API 계약 테스트 | 100% 통과 |
| 이벤트 필수 필드 | 누락 0건 |
| 비용 계산 | 샘플 케이스 오차 ±5% |
| 정책 차단 | 기대 코드 반환 |
| 기본 E2E | 1개 이상 성공 |

## 5. 샘플 테스트 데이터

- 사용자 3명
- 팀 2개
- 서비스 3개
- Workflow 2개
- 정책 3개
